# Aegisub YouTube 사용 안내

갱신: 2026-09-15-15-13-04 KST. YouTube 통합의 최신 네이티브 소스 SHA는 `861ee477d926b5b5b709180ed404a9af3c7f8ae1`이며, 병합된 ARM64 SHA `5601ed225aef1ecf8bb58f737b4142883d603bd7`를 기반으로 합니다. 현재 macOS ARM64 패키지는 [2026-09-15-02-16-01-aegisub-youtube-arm64](../artifacts/2026-09-15-02-16-01-aegisub-youtube-arm64)입니다. 이 문서는 구현과 재현 방법을 설명하며, 현재 패키지 증거는 별도 [검증 문서](2026-09-15-15-13-04-youtube-verification.ko.md)에 기록했습니다. 아래의 날짜가 명시된 기존 관찰은 당시 범위를 유지합니다.

기존 Aegisub의 ASS 편집, 오디오 타이밍, Lua 자동화 작업 흐름을 유지합니다. YouTube 기능은 변환, 호환성 진단, 생성한 YTT에서 만든 근사 미리보기, 선택적인 실제 YouTube 플레이어 확인을 추가합니다.

**macOS 설치와 실행.** macOS 패키지는 Apple Silicon ARM64와 macOS 26 이상을 대상으로 합니다. 최소 macOS 버전은 기반 네이티브 빌드에서 이어받았습니다. 최종 사용자는 Rosetta나 개발용 .NET SDK/런타임을 설치할 필요가 없습니다. 실제 플레이어 기능에는 별도로 설치한 Google Chrome이 필요하며, Chrome은 번들에 없습니다.

전달받은 ZIP을 풀고 `Aegisub YouTube.app`을 실행하세요. 함께 제공되는 `Samples`, 안내서, 감사 결과와 체크섬 파일을 보관하세요. 패키지는 **ad-hoc 서명이며 Developer ID 서명·Apple 공증(notarization)은 되어 있지 않습니다.** 서명만으로 다운로드한 앱의 Gatekeeper 통과가 보장되지는 않습니다.

배포 출처를 신뢰하여 실행을 허용하려면 먼저 앱 열기를 시도한 뒤 **시스템 설정 → 개인정보 보호 및 보안 → 보안 → 열기 → 확인 없이 열기(Open Anyway)**에서 인증하세요. 예외 버튼은 실행 시도 후 약 한 시간 동안 표시됩니다. Gatekeeper를 시스템 전체에서 끄지 마세요. [Apple 안내](https://support.apple.com/guide/mac-help/open-a-mac-app-from-an-unknown-developer-mh40616/mac)를 참고하세요.

**Windows x86_64 설치와 실행.** 설치 프로그램과 portable 패키징 규칙은 `aegisub.exe`가 있는 폴더를 기준으로 `youtube\aegisub-youtube.exe`에 self-contained helper를 포함합니다. 런타임 DLL과 라이선스 파일을 포함한 `youtube` 폴더 전체를 `aegisub.exe` 옆에 유지하세요. helper 실행 파일에는 이 동봉 파일들도 필요합니다. 최종 사용자는 별도의 .NET SDK/런타임을 설치할 필요가 없습니다. 실제 플레이어 기능에는 Google Chrome 또는 Microsoft Edge를 별도로 설치하세요.

**Windows 런타임 검증(2026-09-15).** 실제 Windows 11 AMD64에서 self-contained helper의 스모크 검사 **16개가 모두 통과**했습니다. [검사 결과](../artifacts/2026-09-15-adrena/windows-smoke-results.json)에는 도움말, golden fixture, 한글 경로·해시·가져오기·원본 보존, 잘못된 입력 거부가 기록되어 있습니다. 실제 Chrome에서 로컬 YTT 재생의 응답 대체 ACK와 세 행의 화면 표시도 확인했습니다. [플레이어 상태](../artifacts/2026-09-15-adrena/windows-player-status.txt)는 응답 YTT의 SHA-256과 ACK를 기록하며, 세 행 표시는 별도의 실제 화면 확인 결과입니다.

**Windows portable 직접 검증을 완료했습니다.** [실행 패키지](../artifacts/2026-09-15-03-00-00-aegisub-youtube-win-x64)는 네이티브 편집기, self-contained helper, 번역, 기본 자동화 스크립트를 포함합니다. ZIP 전체를 쓰기 가능한 폴더에 풀고 `aegisub.exe`를 실행하세요. 실제 Windows 11 AMD64의 한글·공백 경로에서 한글 ASS 열기, 파일 → YouTube 변환, 호환성 진단, YTT·ASS·manifest 내보내기를 직접 확인했습니다. 샘플 3행 → 이벤트 55개, 22,904바이트, UI 표시 1,129ms였으며 내보낸 YTT 해시도 manifest와 일치했습니다. [검증 기록](../artifacts/2026-09-15-adrena/windows-native-qa.json), [진단 화면](../artifacts/2026-09-15-adrena/windows-native-diagnostics.png), [내보내기 화면](../artifacts/2026-09-15-adrena/windows-native-export.png).

이 Windows 표시 설정에서는 첫 YouTube 창의 일부 항목이 잘리므로 오른쪽 아래 모서리를 끌어 창을 넓히세요. 내보내기 선택 목록은 한 번에 한 행만 보일 수 있으며 위·아래 키로 이동할 수 있습니다. 전달본에는 별도 Avisynth/VapourSynth 플러그인, DependencyControl, 사전, VC 재배포 설치 프로그램이 포함되지 않습니다. 기본 자막 편집·YouTube 변환을 검증한 portable 묶음이며 전체 설치 프로그램 및 이 선택 구성요소는 검증하지 않았습니다. 새 Windows의 VC 런타임 설치 필요 여부와 네이티브 영상 미리보기는 이번 Windows GUI 검사 범위에 포함되지 않았습니다.

[CI 실행](https://github.com/Tygb99/Aegisub-arch1t3cht/actions/runs/34873355050)은 Windows 네이티브 빌드와 C++ 테스트 354개를 통과했습니다. helper 잠금 복원이 NU1004로 실패한 뒤 `-p:RuntimeIdentifier=win-x64`로 수정했고, 별도 실제 Windows SDK 10.0.301에서 빌드·도움말 및 [16개 스모크 검사](../artifacts/2026-09-15-adrena/native-helper-smoke-results.json)를 통과했습니다. 잠금 검증은 유지합니다. 전달본 helper는 앞서 실제 Windows에서 검증한 cross-published 바이너리이며, 별도 native-build helper와 빌드 경로가 다릅니다. CI 전체 설치 프로그램 성공을 주장하지 않습니다. 기존 wx-master 작업의 낡은 의존성 패치 실패는 남아 있으며 macOS ARM64 및 Ubuntu 작업은 통과했습니다.

**편집기 사용 순서.**

1. 자신의 ASS와 영상을 열거나, 제공된 `Samples/한글 샘플.ass`를 자신의 영상 또는 1280×720 더미 영상과 함께 여세요. `Samples/한글 샘플.srt`는 일반 텍스트 호환용이며 영상은 제공하지 않습니다.
2. **파일 → YouTube(File → YouTube)**를 여세요. 대화상자에는 변환 설정, 선택 행 효과, 호환성 진단이 있습니다.
3. 변환이 끝나면 `영상 화면에서 YouTube 변환 결과 보기 (시각적 근사치)`를 켜고 꺼 원본 ASS와 실제 생성된 YTT에서 만든 근사 화면을 비교하세요. 양쪽 모두 Aegisub의 기존 재생·탐색 시계를 사용합니다.
4. `영상·자막 편집`으로 편집 화면에 돌아가도 백그라운드 변환은 계속됩니다. 파일 → YouTube를 다시 열어 상태를 확인하거나 `다시 변환` / `변환 취소`를 사용하세요.
5. 진단 항목을 더블클릭하면 해당 자막 행을 선택하고 시작 시점으로 이동합니다. 관련 경고를 확인한 다음 `내보내기 묶음…`을 선택하세요.

스타일 변환 설정은 ASS의 `[Script Info]`에 `Aegisub Youtube Options` 항목으로 저장됩니다. ASS를 저장해야 설정도 남습니다. 설정 변경은 실행 취소(Undo)에 포함되며 미리보기와 내보내기는 같은 설정 스냅샷을 사용합니다. 글꼴 배율은 `Default` 스타일의 글꼴 크기에 상대적이므로 기준을 유지하세요. `Default`가 없으면 첫 스타일을 기준으로 삼습니다.

**PlayRes와 자막 크기.** 640×360은 모든 경우의 해결책이 아닙니다. 1920×1080 기준 자막에서 PlayRes만 640×360으로 바꾸면 기존 픽셀 태그인 `\pos(960,980)` 등이 새 좌표 범위 밖에 남습니다. 변환기는 이 예의 YTT 좌표를 `(ah,av)=(100,100)`으로 제한합니다.

전체 리샘플링은 스타일 글꼴 크기, 명시적 위치, 여백, 테두리와 그림자를 포함한 모든 픽셀 값을 3으로 나눕니다. 기본 출력 프로필(크기 1, X/Y 보정 0)이라면 `\pos(960,980)`은 `\pos(320,326.667)`이 되고, 위치와 PlayRes가 함께 줄어 YTT `(50,92)`를 유지합니다. 모든 스타일 크기를 60에서 20으로 줄여도 글꼴/기준 스타일 비율(`60/60 = 20/20 = 1`)과 YTT pen `sz=100`이 유지됩니다. 따라서 전체 리샘플링은 이 정규화 좌표와 글꼴 비율을 보존하며, 그 자체로 YTT 자막을 작게 만들거나 모바일 배치의 정확성을 입증하지는 않습니다. 대상 플레이어·기기를 별도로 확인하세요. 아래의 제한된 기기 관찰만으로 모든 환경의 호환성을 보증할 수는 없습니다.

선택 행 효과는 ASS를 변경하며 실행 취소할 수 있습니다. 페이드·변형 시간은 행 시작에 대한 밀리초이고, ASS 가라오케 `\k` 시간은 **10ms 단위**입니다(500ms = `\k50`). 효과 UI는 밀리초를 입력받아 가라오케 단위로 변환합니다. 색상 입력은 RRGGBB이며 원시 ASS 색상 태그는 ASS 문법을 따릅니다.

출력 프로필의 크기는 배수이며 X/Y 보정은 ASS PlayRes 픽셀 단위로 명시적 위치에 적용됩니다. 모바일 프로필은 스타일을 단순화하고 drawing 모드 내용을 제거하면서 일반 텍스트를 남깁니다. 원본 ASS는 보존됩니다. **기기 관찰은 아래 사례에 한정되며, 이 프로필이 모바일 렌더링을 보증하지는 않습니다.**

**기기 관찰(2026-09-15 사용자 보고).** Android 전체 화면에서는 세 행이 겹치지 않고 각각 표시되는 것을 사용자가 확인했습니다. 남은 차이는 검은 배경과 글꼴 표현이며, 이 사례에서는 플랫폼 한계로 받아들이기로 했습니다. iPhone에서는 앞서 위치를 보정한 버전에서도 마지막 행이 깜빡인다고 보고했습니다.

두 번째 단일 테두리 변형본은 네 겹의 효과 복사본을 줄여 YTT `<p>` 이벤트 수를 7,932개에서 1,983개로 줄였으며 텍스트·색상·타이밍을 유지합니다. 사용자는 이 단일 테두리 버전에서도 iPhone 깜빡임을 계속 확인했으므로, 효과 복사본만 줄이는 것으로는 이 사례가 해결되지 않았습니다.

**세 번째 변형본을 최종본으로 선택했습니다.** 세 행을 하나의 여러 줄 YTT 자막 블록에 담은 이 버전은 업로드를 완료했고, 데스크톱 플레이어에서 세 행이 표시되는 것을 확인했습니다. **사용자는 iPhone에서 다시 열어 확인한 결과 28–31초 구간의 깜빡임이 사라졌다고 확인했습니다.** 이 결과는 사용자가 확인한 기기와 해당 구간에 한정되며, 모든 iOS 기기나 재생 환경에서 같은 결과를 보증하지는 않습니다.

**플레이어별 배경과 글꼴 차이.** [고정된 upstream README의 Limitations](https://github.com/arcusmaximus/YTSubConverter/blob/b186a40bc21e58a8c9651cf616cbb5e80425dfc6/README.md#limitations)는 모바일 앱이 지정한 배경색·투명도와 관계없이 검은 자막 상자를 표시하는 제한을 설명합니다. [YttDocument의 관련 주석](https://github.com/arcusmaximus/YTSubConverter/blob/b186a40bc21e58a8c9651cf616cbb5e80425dfc6/YTSubConverter.Shared/Formats/YttDocument.cs#L539-L546)도 이 배경 제한과 Android용 어두운 글자 보정이 iOS의 다른 투명도 처리 때문에 같은 방식으로 작동하지 않는다고 설명합니다. 데스크톱·Android·iOS의 표현이 일치한다고 보장할 수 없으며, PlayRes를 640×360으로 바꾸거나 전체 리샘플링해도 검은 배경이나 글꼴 차이가 제거된다는 보장은 없습니다.

**내보내기와 가져오기.** 내보내기는 `result.ytt`, 설정을 포함한 `source.ass`, `compatible.srt`와 변환 manifest를 제공할 수 있습니다. SRT에는 스타일·위치·효과가 보존되지 않습니다. ASS를 편집 원본으로 유지하고 YTT는 변환 결과로 취급하세요.

`YTT → 편집용 ASS`는 YTT/SRV3를 새로운 ASS 경로로 변환하며 현재 문서는 유지합니다. 완료 후 파일 → 자막 열기로 여세요. 펼쳐진 효과가 원래 작성 태그로 모두 복원되지는 않을 수 있습니다.

Studio 업로드는 채널 담당자가 별도로 수행하는 작업입니다. 선택한 최종 YTT는 승인된 Aside 로그인 세션을 통해 업로드하여 [아드레나](https://www.youtube.com/watch?v=jOYcCNgJDn0)에 게시했습니다. PC 재생에서 색이 있는 세 행을 확인했고, iPhone에서 영상을 다시 연 뒤 28–31초에 깜박임이 사라졌다고 사용자가 확인했습니다. [최종 파일과 해시 기록](../artifacts/2026-09-15-adrena/final-subtitles.json)을 참조하세요. ASS/YTT를 보관하고 게시된 플레이어를 별도로 확인하세요. Studio 편집이 업로드한 스타일을 제거할 수 있다는 주의는 [고정된 YTSubConverter README](https://github.com/arcusmaximus/YTSubConverter/blob/b186a40bc21e58a8c9651cf616cbb5e80425dfc6/README.md#uploading-to-the-video)에 근거하며, Studio 편집기의 미리보기만으로 판단할 수 없습니다.

**실제 YouTube 플레이어 확인.**

1. macOS에는 Google Chrome을, Windows에는 Chrome 또는 Microsoft Edge를 설치한 뒤 `https://www.youtube.com/watch?v=RKK7wGAYP6k` 같은 공개 watch URL과 기존 수동 자막 트랙의 언어 코드를 입력하세요.
2. 최신 변환이 완료되면 `실제 플레이어 시작`을 누르세요. 전용 브라우저 창에서 정확히 그 언어의 CC 트랙을 켜세요. 자동 생성·번역 자막은 제외하며 없는 트랙을 만들지는 않습니다.
3. 편집 후 다시 변환되면 CC를 **껐다 켜서** 새 로컬 자막을 요청하세요. 일치하는 응답의 성공 ACK를 받으면 앱 상태가 갱신됩니다. 실제 표시 화면도 함께 확인하세요.
4. `플레이어 종료`를 누르면 helper가 자신이 시작한 브라우저 프로세스 트리를 종료하고 고유 임시 프로필을 삭제합니다.

Windows의 [브라우저 탐색](../tools/youtube/PlayerPreview.cs)은 Program Files, Program Files (x86), Local AppData 순서로 Chrome을 찾은 다음 같은 위치에서 Edge를 찾고, 처음 발견한 실행 파일을 사용합니다. macOS 기본 경로는 `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`입니다. 다른 설치 경로를 쓰려면 Aegisub 실행 전에 `AEGISUB_YOUTUBE_CHROME`을 브라우저 실행 파일의 전체 경로로 설정하세요. 두 플랫폼 모두 이 설정이 기본 탐색보다 우선합니다. 예를 들어 PowerShell에서 경로를 자신의 환경에 맞게 바꾼 뒤 같은 셸에서 Aegisub을 실행하세요.

```powershell
$env:AEGISUB_YOUTUBE_CHROME = 'C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe'
& 'C:\path\to\Aegisub\aegisub.exe'
```

실제 앱에서 CC off/on에 따른 갱신과 재ACK 상태를 **2026-09-14 17:02:58 KST**에 관찰했습니다. 데스크톱 관찰이며 모바일 검증은 아닙니다. 대기 상태는 일치하는 수동 언어 트랙 요청이 아직 없다는 뜻일 수 있습니다.

helper는 루프백 Chrome DevTools Protocol(CDP)을 사용하여 `https://www.youtube.com/api/timedtext*`만 가로채고, 영상·언어가 일치하는 요청에 로컬 YTT 바이트로 응답합니다. 프록시, 인증서 설치, TLS 우회, 자막 업로드를 사용하지 않습니다. 일반 YouTube 영상 재생에는 네트워크를 사용합니다.

응답 대체는 명령 ID가 연결된 성공 CDP ACK를 받은 뒤에만 확인됩니다. `status.txt` 첫 줄의 `SHA256 <hash>`는 실제 응답 바이트의 해시이며, 네이티브 UI는 최신 준비 리비전과 YTT 해시가 일치할 때만 확인 상태를 인정합니다. 응답 동일성을 확인하는 것이며 자막 배치나 픽셀 일치를 보증하지는 않습니다. 세션의 `protocol.log`로 조사할 수 있습니다.

편집하면 이전 결과를 무효화하고 300ms 디바운스 후 변환합니다. manifest에는 입력·설정·YTT SHA-256, 엔진과 패치 리비전, 프로필, 이벤트 확장 정보, `visualApproximation=true`가 기록됩니다. 최신 네이티브 GUI 관찰은 SHA `861ee477d926b5b5b709180ed404a9af3c7f8ae1`과 병합된 ARM64 SHA `5601ed225aef1ecf8bb58f737b4142883d603bd7`를 기반으로 [최신 패키지](../artifacts/2026-09-15-02-16-01-aegisub-youtube-arm64)에서 수행했습니다. 한글 로캘에서 변환과 호환성 진단을 직접 관찰했으며, [mac-regex-diagnostics.png](../artifacts/2026-09-15-adrena/mac-regex-diagnostics.png)에 fade·transform·ytkt 경고가 기록되어 있습니다. 세 행 샘플은 이벤트 55개, 22,904바이트로 변환됐고 **859ms**가 걸렸습니다. 이전 GUI 관찰 범위 **469–830ms**와 이전 1,405ms GUI 관찰은 과거 증거이며, **4초 영상 QA**는 [이전 패키지](../artifacts/2026-09-15-01-00-46-aegisub-youtube-arm64)에서만 수행한 과거 **734ms** 관찰입니다. 최신 패키지의 측정값으로 해석하면 안 됩니다. 특정 관찰값이며 일반적인 성능 보증이나 보편적 벤치마크는 아닙니다.

변환기 기반은 [arcusmaximus/YTSubConverter b186a40](https://github.com/arcusmaximus/YTSubConverter/tree/b186a40bc21e58a8c9651cf616cbb5e80425dfc6)에 고정되어 있습니다. 저장소의 [포크 전체 패치](../tools/youtube/patches/independent-justification.patch)는 [DO0OG independent-justification 브랜치](https://github.com/DO0OG/YTSubConverter/compare/b186a40bc21e58a8c9651cf616cbb5e80425dfc6...c460cca9f5b37aa0e98e460007f7379df5732d05)의 `27472674e6217f4f3407bb855476529e6dd5412e`와 `c460cca9f5b37aa0e98e460007f7379df5732d05` 두 커밋을 포함합니다. MIT 고지는 [동봉 라이선스](../tools/youtube/patches/YTSubConverter-LICENSE)에 유지하며 Aegisub 전체를 MIT로 재라이선스하는 것은 아닙니다.

패치는 YTT `ap`(앵커)와 `ju`(텍스트 정렬)를 독립적으로 읽고 복제하고 기록하며, 서로 다른 스타일 풀 항목도 구분합니다. 프로젝트의 [ASS 연결 패치](../tools/youtube/patches/ass-justification.patch)와 [태그 처리기](../tools/youtube/upstream-support/AssJustificationTagHandler.cs)는 **사용자 정의 확장** `\ytju0`(왼쪽), `\ytju1`(오른쪽), `\ytju2`(가운데)를 추가하고 `\an`은 앵커로 유지합니다. 다른 렌더러가 표준 ASS로 지원하는 기능은 아닙니다.

**편집용 ASS/YTT 데이터에는 독립 정렬이 보존되지만 시각적 표현은 미완성입니다.** 기존 ASS 시각화기는 앵커를 기준으로 정렬하므로 독립 정렬된 여러 줄 텍스트가 다르게 보일 수 있습니다. 불일치가 있으면 manifest의 `visualDiagnostics`에 `YTJU_VISUAL_ALIGNMENT`를 기록하고 `visualIndependentAlignmentPreserved=false`로 표시합니다. 가져오기는 stderr에 JSON 경고를 출력하고 네이티브 진단도 `ytju`를 경고합니다. `result.ytt`를 실제 플레이어에서 확인하세요. 정렬 플래그가 true여도 해당 불일치가 없다는 뜻이지 모든 화면이 정확하다는 뜻은 아닙니다.

**Windows x86_64에서 저장소 루트 기준 빌드.** PowerShell과 .NET SDK **10.0.301 또는 [SDK 고정 설정](../tools/youtube/global.json)이 허용하는 이후 패치 버전**이 필요하며, PATH에 `git`과 `tar`가 있어야 합니다. 네이티브 편집기에는 기존 Windows 빌드 의존성도 필요합니다. 설치 프로그램과 portable 패키징이 사용하는 디렉터리로 helper를 게시하세요.

```powershell
.\tools\youtube-build.ps1 -OutputDirectory build/youtube
```

[PowerShell 스크립트](../tools/youtube-build.ps1)는 `-p:RuntimeIdentifier=win-x64`를 사용해 잠금 복원을 수행하고 고정 다운로드와 패치를 검증한 뒤 .NET 런타임 **10.0.9**를 포함한 self-contained `win-x64`를 게시합니다. 지정한 출력 디렉터리를 다시 만들며 런타임 파일과 변환기/.NET 고지를 포함합니다. Windows에서는 게시한 helper를 `--help`로 실행합니다. 설치 프로그램과 portable 규칙은 `build/youtube`를 `aegisub.exe` 옆에 복사하므로 로컬 빌드에서도 이 배치를 유지하세요. 이 helper 빌드만으로 네이티브 설치 프로그램이 검증되는 것은 아니며, 전체 설치 프로그램은 이번 전달 검증 범위 밖입니다.

**macOS에서 저장소 루트 기준 빌드.** 개발자는 기반 네이티브 빌드 의존성과 .NET SDK **10.0.301**이 필요합니다([SDK 고정](../tools/youtube/global.json), 이후 패치 버전 허용). helper는 런타임 **10.0.9**를 포함하는 self-contained `osx-arm64` 대상입니다([프로젝트](../tools/youtube/Aegisub.Youtube.csproj)).

```bash
bash tools/youtube-package.sh
# 대안: build-arm64/Aegisub.app이 이미 있고 최신일 때만 사용
bash tools/youtube-package.sh --reuse-core
# helper만 다시 빌드하고 CLI 회귀 검증 재현
bash tools/youtube-build.sh
```

[전체 패키지 스크립트](../tools/youtube-package.sh)는 네이티브 코어/번들, helper와 AppKit 라이브러리를 빌드하고 서명·ARM64 의존성 감사를 수행합니다. DOTNET_ROOT와 개발자 PATH 없이 helper를 스모크 검사한 뒤 `artifacts/` 아래에 타임스탬프 전달 폴더, ZIP, SHA-256 파일을 만듭니다. `--reuse-core`는 네이티브 재빌드를 건너뛰지만 helper는 다시 빌드하며, 기존 번들과 감사 도구 환경이 필요합니다.

[helper 빌드 스크립트](../tools/youtube-build.sh)는 고정 다운로드를 검증하고 `tools/youtube/obj`의 별도 소스 복사본에 패치를 적용합니다. 공식 Microsoft **10.0.9 osx-arm64 런타임**과 hostfxr을 덮어 넣어 배포 helper의 Homebrew 런타임 외부 Brotli 의존성을 해결합니다. 변환기/.NET 고지를 포함하고 변경된 라이브러리를 다시 서명합니다. 임의의 Homebrew 런타임 복사본으로 대체하지 마세요. npm은 필요하지 않습니다.

[Ruby 회귀 검사기](../tools/youtube-test.rb)는 고정 golden fixture와 해당 `StyleOptions.xml`, 태그 해석·타이밍, 앵커/정렬 27개 조합과 좌표 왕복, 정렬 진단, 원본 보존, 모바일 drawing 제거를 검사합니다. golden 비교에서는 선두 UTF-8 BOM만 제거합니다. XML 재포맷이나 스타일 옵션 생략은 비교 기준을 바꿉니다.

**macOS 번들 helper CLI.** 패키지 자리표시자를 실제 압축 해제한 전달 디렉터리로 바꾸고 새 출력 경로를 사용하세요. 한글 fixture는 저장소의 [tests/youtube-fixtures](../tests/youtube-fixtures)에도 있습니다.

```bash
PACKAGE="/path/to/extracted/delivery"
APP="$PACKAGE/Aegisub YouTube.app"
HELPER="$APP/Contents/MacOS/youtube/aegisub-youtube"
OUT="$(mktemp -d)"
"$HELPER" --help
"$HELPER" preview "$PACKAGE/Samples/한글 샘플.ass" "$OUT/preview"
"$HELPER" import "$OUT/preview/result.ytt" "$OUT/imported.ass"
# 변환 설정 XML을 명시하는 선택적 사용법:
# "$HELPER" preview INPUT.ass NEW_OUTPUT_DIRECTORY STYLE_OPTIONS.xml
# 선택적인 실제 플레이어: en이 기존 수동 트랙과 일치해야 함
"$HELPER" player 'https://www.youtube.com/watch?v=RKK7wGAYP6k' \
  "$OUT/preview/result.ytt" en "$OUT/player"
# 다른 터미널에서 같은 OUT 값을 설정한 후: touch "$OUT/player/stop"
```

CLI preview는 ASS 메타데이터에서 GUI 설정을 자동 추출하지 않습니다. 해당 설정을 재현하려면 `STYLE_OPTIONS.xml`을 명시하세요. preview 결과는 `result.ytt`, `preview.visual.ass`, `compatible.srt`, `source.ass`, `manifest.json`입니다.

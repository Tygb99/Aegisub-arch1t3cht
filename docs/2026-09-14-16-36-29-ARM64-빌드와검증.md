# Aegisub macOS ARM64 빌드와 검증

코드·번들·CI 검증 결과를 기록한다. 사용자가 한글 입력 상태의 단축키·받침 수정·재생을 정상으로 확인했다. 아래의 미검증 항목은 별도로 구분한다.

- 기준 전체 SHA: `1ba7131916d169e4eb8c7bf77b299ea4cbadbf00`.
- 작업 디렉터리: `/Volumes/ssd/Codex/Aegisub`, 작업 브랜치 `codex/macos-arm64`.
- 기존 `.codegraph`를 보존했다. 초기 디렉터리에 소스 체크아웃과 사용자 코드 변경은 없었다.
- GitHub CLI 계정은 Tygb99이며 대상에 쓰기 권한이 없다. 사용자 승인으로 [Tygb99 포크](https://github.com/Tygb99/Aegisub-arch1t3cht)를 만들고 `personal` 원격으로 등록했다. 원래 `origin`을 보존했다.
- 첫 산출물은 ARM64 전용이며 macOS 26.0 이상을 대상으로 한다. 현재 실제 의존성 28개 Mach-O의 `LC_BUILD_VERSION` 최소 버전이 모두 26.0이다. 이전 macOS 지원을 주장하지 않는다.
- M1을 포함한 Apple Silicon을 대상으로 한다. 로컬 실기는 Apple M4, macOS 26.6.2, SDK 26.5, Apple Clang 21이다. `-march=native`·`-mcpu=native`를 사용하지 않는다. GitHub M1 Virtual 러너에서도 ARM64 프로세스·컴파일러와 실제 H.264 하드웨어 경로를 확인했다. 별도 M1 실물 Mac은 미검증이다.

## 빌드·패키징 명령

네이티브 Apple Silicon 셸, Xcode/명령줄 도구, `/opt/homebrew`의 ARM64 의존성이 필요하다. 정확한 릴리스 소스를 다시 빌드할 때는 새 체크아웃에서 `git checkout --detach 1963a07cedfe46905e23292cdc3b06f39be37ba8`을 먼저 실행한다. 아래 명령은 준비된 소스 체크아웃에서 실행한다. 직접·전이 의존성 32개 버전·소스·recipe·ARM64 bottle SHA-256은 `tools/macos-homebrew-lock.json`에 고정한다. 로컬 빌드 시작 시 불일치를 거부하고 자동으로 환경을 바꾸지 않는다. CI의 일회용 러너에서만 `--restore-ci`로 기록된 bottle을 복원한다. npm은 사용하지 않는다.

```sh
cd /Volumes/ssd/Codex/Aegisub
bash tools/macos-arm64-build.sh
export PATH="$PWD/.deps/wx/bin:$PWD/.venv/bin:/opt/homebrew/bin:/usr/bin:/bin:/usr/sbin:/sbin"
export PKG_CONFIG_PATH="$PWD/.deps/ffmpeg/lib/pkgconfig:/opt/homebrew/opt/icu4c@78/lib/pkgconfig"
meson compile -C build-arm64
meson compile -C build-arm64 osx-bundle
python tools/macos-arm64-audit.py build-arm64/Aegisub.app --output artifacts/arm64-audit.json
meson compile -C build-arm64 osx-build-dmg
```

커밋 후에는 일반 `meson compile`을 먼저 실행해 실행 파일과 Info.plist의 버전 메타데이터를 일치시킨다. CI 재현은 `gh workflow run ci.yml --repo Tygb99/Aegisub-arch1t3cht --ref codex/macos-arm64`로 실행할 수 있다.

Meson 1.7.2의 재설정 시 컴파일 옵션 캐시 문제를 피하려고 `meson configure` 다음 `setup --reconfigure --clearcache`를 실행한다. 실제 C·C++·Objective-C·Objective-C++ 명령의 ARM64·최소 macOS 옵션 반영을 확인했다.

홈 경로를 바꾸는 대신 `CFFIXED_USER_HOME`으로 검증용 앱 설정을 분리한다. 사용자 원본 대신 `artifacts/qa/한글 경로`의 새 테스트 자막과 영상을 사용했다. 영상은 `h264_videotoolbox -allow_sw 0`으로 인코딩했다.

## 한글 입력기 문제와 수정 검증

사용자가 첫 포커스에서 받침이 입력되지 않는다고 보고했다. 기존 macOS 코드가 Cocoa 범위를 UTF-8 바이트로 전달하고 문맥 조회·명시된 교체 범위를 누락함을 확인했다. UTF-16 변환, 조합 문맥, 받침 교체, 조합 확정과 실행 취소 보존을 수정했다.

직접 NSTextInputClient 회귀 테스트 20개와 AddressSanitizer가 통과했다. 사용자는 수정본에서 첫 입력과 재포커스 모두 ‘한글’로 정상 조합된다고 확인했다. 자동화 도구의 비활성 창 합성 키에서는 자모 분리가 관찰돼 사용자 물리 입력 결과와 구분했다. 앱의 문맥 메뉴로 한글 선택·복사·붙여넣기를 실행하고, 실행 취소·다시 실행 결과를 저장 파일로 확인했다. 빈 commit 삭제와 조합 일부 확정도 20개 검사에 포함한다.

새 수정의 임시 wxString에서 UTF-8 포인터를 보관한 오류가 메모리 검사에서 발견됐다. 앱에 반영하기 전 문자열 수명을 수정했고 ASan 재검사를 통과했다. 테스트 도구의 종료 오류를 최종 앱 성공으로 숨기지 않는다.

사용자가 한글 입력기에서 ⌘A가 동작하지 않고 ABC에서는 동작한다고 추가 확인했다. Cocoa 이벤트는 `characters=a`, `charactersIgnoringModifiers=ㅁ`을 전달하고, wxWidgets가 입력기 키보드 레이아웃 없이 이를 처리하면 키 코드가 0으로 소실됐다. ASCII Command 문자와 비ASCII unmodified 문자가 함께 있는 경우에만 이벤트를 보정해 기존 wxWidgets 단축키 처리로 전달한다. 명령별 동작이나 사용자 단축키 설정을 새로 매핑하지 않는다.

같은 최종 회귀 테스트 28개에서 수정 전 4개 실패, 수정 후 28개와 ASan 모두 통과했다. 실제 Cocoa 키 이벤트와 STC를 사용해 선택·복사·붙여넣기·실행 취소, 메뉴 우선순위와 Control 구분을 검증했다. 로그는 `artifacts/qa/2026-09-14-15-58-28-scintilla-ime-command-final-before-asan.log`, `artifacts/qa/2026-09-14-15-57-48-scintilla-ime-command-final-asan.log`이다. 별도 위치의 수정본에서 ⌘A 전체 선택, ⌘C·⌘V 한글 복사·붙여넣기, ⌘Z·⇧⌘Z 취소·재실행을 직접 조작해 확인했다. 이어 사용자가 한글 입력 상태의 ⌘A·⌘C·⌘V·⌘Z·받침 수정과 재생음 확인 질문에 “잘됨”으로 회신했다. `artifacts/qa/command-a-fixed-gui.png`, `command-cv-fixed-gui.png`, `command-z-fixed-gui.png`, `command-redo-fixed-gui.png`와 저장 자막이 증거다.

오디오 화면에서 종료 위치를 바꾸고 적용한 결과 첫 자막의 종료 시간이 5.00초에서 5.59초로 저장됐다. `artifacts/qa/한글 경로/레티나 음향 타이밍.ass`와 `artifacts/qa/retina-audio-timing-gui.log`에 결과를 남겼다.

로컬의 하드웨어 정확성 검사는 H.264에 대한 결과다. 사용한 FFmpeg 7.1.2 H.264 경로는 `RequireHardwareAcceleratedVideoDecoder=true`를 요구하며 실제 VideoToolbox 프레임을 받았다. HEVC 등 다른 코덱의 하드웨어 동작까지 확인했다고 주장하지 않는다. CI에서도 H.264 API의 hardware_frames=139, software_frames_in_hardware_context=0, 공급자의 hardware_frames=119를 확인했다.

## CI와 환경 보존 기록

첫 CI는 같은 ARM64 bottle을 복원한 후 변경 가능한 Homebrew `tap_git_head`와 설치 과정에서 추가되는 런타임 의존성 메타데이터 때문에 검증에 실패했다. 바이너리 버전·소스·recipe·bottle 해시 불일치는 아니었다. 변경 가능한 기록은 비교에서 분리하고 모든 실제 의존성을 전체 lock과 대조하도록 수정했다. 두 번째 CI에서 정확한 bottle 복원부터 산출물 업로드까지 통과했다. 의존성 캐시는 SDK·Clang·아키텍처·최소 OS·빌드 스크립트·lock 해시가 모두 같은 경우만 재사용한다.

테스트 자동화의 보조 창이 기본 사용자 프로필로 한 차례 실행되어 테스트 최근 파일 기록과 마지막 자막 폴더를 남겼다. `artifacts/qa/2026-09-14-15-38-00-default-profile-before-qa-cleanup/`에 config/mru를 백업하고 테스트 항목만 제거했다. 마지막 자막 폴더는 빈 값으로 돌렸으나 테스트 전 값은 백업하지 못해 정확히 복원했다고 주장하지 않는다. 이후에는 앱의 절대 경로와 분리 프로필을 직접 지정했다. 이는 자동화 과정의 부수 효과이며 자막 원본 내용 변경은 없다.

## 기존 문제와 이번 변경의 구분

- 기존: Intel 전용 번들 메타데이터, 불완전한 전이 의존성 처리, sudo 설치, 슬래시가 있는 브랜치에서 version.sh의 sed 실패, 최신 Clang과 Boost 헤더 문법, wxWidgets 공유 라이브러리의 비공개 IME 심볼, Cocoa 범위 계약 누락. 이번 작업에서 확인하고 해당 부분을 수정했다.
- 이번 변경에서 발견 후 수정: 입력기 UTF-8 임시 버퍼 수명 오류, CI Homebrew 메타데이터 비교 오류, HFS+ 설치 이미지에서 새 한국어 고지 파일명의 정규화에 따른 서명 오류. 회귀 테스트·ASan·CI·마운트 검사의 실패 원문을 남기고 수정 후 다시 통과했다.
- 기존 컴파일 경고: MatroskaParser의 초기화 경고, Hunspell 폐기 예정 API, OpenGL 폐기 예정 경고 등이 남아 있다. 관계없는 전면 리팩터링은 하지 않았다.

## 배포 서명과 남은 검증

현재 서명은 로컬 실행을 위한 ad hoc 서명이다. Developer ID 배포 서명·공증은 수행하지 않았다. 별도 Developer ID 인증서와 공증 권한이 필요하며, 인증 정보를 문서나 저장소에 저장하지 않는다.

손상 영상은 BestSource와 FFmpegSource의 오류 처리 후 앱으로 복귀했고 손상 ASS는 형식 오류를 알린 뒤 복귀했다. 파형 설정 `Spectrum=false`가 종료 시 테스트 프로필에 저장되고 별도 위치 앱 재실행 후 복원됐다. 최종 DMG를 읽기 전용으로 마운트하고 안의 앱을 `/Volumes/ssd/Codex/Aegisub-ARM64-standalone/Aegisub.app`으로 복사했다. 이미지를 해제한 뒤 LaunchServices로 실행해 저장한 한글 자막·영상·파형 설정이 복원됨을 확인했다(`artifacts/qa/final-installed.png`). `lsof`에 개발 Homebrew·`.deps`·빌드 디렉터리에서 로드된 파일이 없고, 실제 모든 비시스템 의존성이 번들 안에서 해결됐다. 별도 M1 실물 Mac과 Homebrew가 없는 별도 GUI 머신을 확보하지 못해 해당 환경은 미검증이다. 하드웨어 정확성 검사는 H.264 fixture로 수행했으므로 HEVC 등 다른 코덱 전반은 미검증이다. ‘프레임/시간으로 이동’ 대화상자도 미검증이다. 해당 모달은 자동화 도구가 제어하지 못했으며 사용자가 닫았다. 슬라이더와 프레임 단위 이동은 실제 앱에서 검증했다.


## 최종 산출물

- 설치 이미지: `/Volumes/ssd/Codex/Aegisub/artifacts/release/Aegisub-ARM64-macOS26.dmg`
- 독립 앱: `/Volumes/ssd/Codex/Aegisub/artifacts/release/Aegisub.app`
- 실제 별도 위치 실행본: `/Volumes/ssd/Codex/Aegisub-ARM64-standalone/Aegisub.app`
- 대응 소스: `/Volumes/ssd/Codex/Aegisub/artifacts/release/2026-09-14-07-21-53-Aegisub-corresponding-sources.tar`
- 해시: `/Volumes/ssd/Codex/Aegisub/artifacts/release/SHA256SUMS`
- ARM64·전이 의존성·서명 보고: `/Volumes/ssd/Codex/Aegisub/artifacts/arm64-audit-final.json`, `/Volumes/ssd/Codex/Aegisub/artifacts/arm64-audit-standalone.json`
- 실제 CI 원문 증거: `/Volumes/ssd/Codex/Aegisub/artifacts/ci/`

DMG를 열어 Aegisub.app을 Applications 또는 원하는 폴더로 복사한다. macOS 26.0 이상이 필요하며 Rosetta와 실행용 Homebrew 설치는 필요하지 않다. 이 산출물은 ad hoc 서명본으로, 인터넷 배포용 Developer ID 서명·공증을 마친 릴리스와 구분한다.

`Contents/SharedSupport/licenses`에는 기존 저작권·라이선스 원문을 보존했고 한국어 안내와 소스 해시 목록을 추가했다. 대응 소스 tar에는 최종 Aegisub 소스 스냅샷, 의존성 소스, 적용 패치와 빌드 설정을 포함한다. 라이브러리 원본/수정 해시 manifest는 경로 수정·개별 서명 직후, 앱 전체 서명 전 단계임을 표시한다. 최종 배포 파일 해시는 위 SHA256SUMS를 사용한다.

LuaJIT 및 lpeg·lfs·luabins 등 네이티브 모듈은 ARM64 실행 파일에 정적으로 연결한다. 외부 Intel Lua 모듈에 의존하지 않으며 내장 런타임 검사와 실제 자동화 매크로에서 실행했다.


## DMG 마운트에서 발견한 서명 문제

`.app`과 ZIP의 서명 검사, DMG 파일 checksum은 통과했지만 실제 HFS+ 이미지를 마운트하자 새 한국어 고지 파일명이 NFC에서 NFD로 바뀌어 리소스 서명이 실패했다. 같은 이름으로 보이는 고지가 추가·누락되었다는 `codesign` 오류를 `artifacts/logs/dmg-installed-check.log`에 보존했다. 이는 이번에 만든 고지 파일명 때문에 생긴 문제다.

고지 내용은 한국어로 유지하고 파일명만 시간 접두사와 `third-party-notices.ko.md`로 바꿨다. 재서명한 앱으로 HFS+ 이미지를 새로 만들고 읽기 전용 마운트 후 엄격 서명을 검증해 통과했다(`artifacts/logs/dmg-seal-test.log`). 최종 DMG도 마운트된 상태에서 28개 Mach-O·서명·실행 파일 일치를 통과했다(`artifacts/arm64-dmg-mounted-audit.json`). 기존 CI 검사에서 놓친 단계이므로 최종 CI에 DMG checksum·실제 마운트·모든 Mach-O 감사·실행 권한·실행 파일 비교·서명·해제를 추가했다. 최종 패키징 커밋은 `1963a07cedfe46905e23292cdc3b06f39be37ba8`이며 [네 번째 CI](https://github.com/Tygb99/Aegisub-arch1t3cht/actions/runs/34817454400)도 전체 성공했다. 마운트된 DMG 감사는 2026-09-14 07:32:27 UTC, 전체 작업은 07:32:46 UTC에 완료됐다. 원문 증거는 `artifacts/ci/34817454400/`에 보존했다.

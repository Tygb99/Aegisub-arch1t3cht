# ARM64 PR 머지 전 수정

독립 리뷰에서 작업 브랜치의 성공한 CI만으로는 예정된 feature PR과 머지 이후 빌드가 검증되지 않는 설정 문제를 발견했다. ARM64 작업의 작업 브랜치 전용 조건을 제거해 워크플로에 등록된 PR·push·수동 실행에 적용한다. 실제 러너 아키텍처와 Rosetta 미사용 검사는 그대로 유지한다.

공통 macOS 번들 스크립트가 ARM64 전용 의존성 폴더와 lock을 항상 요구하던 회귀도 수정했다. 새 Meson 옵션 `bundle_arm64_licenses`의 기본값은 false이며 `tools/macos-arm64-build.sh`는 true로 설정한다. 전용 배포에서는 라이선스·대응 소스 수집 실패가 계속 패키징을 중단한다. 일반 Meson 번들에서는 기존 빌드 방식에 ARM64 lock을 강제하지 않는다. 이 선택은 일반 빌드의 의존성 재배포 고지를 자동으로 완성한다는 뜻은 아니다.

회귀 fixture에서 일반 번들에 수집기를 강제하는 기존 코드의 실패를 먼저 확인했다. 수정 후 실제 Meson 설치·Mach-O 실행·서명까지 포함한 번들 fixture와 패키징·감사 47개가 모두 통과했다. 셸 문법과 diff 공백 검사도 통과했다. 이 수정은 앱 런타임 소스·wxWidgets·Lua·영상·오디오 코드를 변경하지 않는다.

공개할 앱과 DMG, 대응 소스 tar는 실제 사용자 입력 검증을 받은 `1963a07cedfe46905e23292cdc3b06f39be37ba8` 산출물로 유지한다. 새 커밋의 빌드·CI 수정은 앞으로의 빌드와 PR 검증에 적용한다. 바이너리를 새 커밋에서 빌드했다고 표시하지 않는다.

기존 `macos-13` CI 행렬은 기준 저장소에서 유지된 항목이다. 공식 러너 지원 종료 때문에 이 행렬의 실행 성공을 보장할 수 없다. 새 macOS 26 ARM64 작업의 결과와 구분한다. Windows·Linux·Intel 전체의 새 실행 검증은 이 수정의 범위에 포함하지 않는다.
